\section{Scope}

Let $S_{1998}$ be the exact classic specification-mode VM state space and
$T:S_{1998}\to S_{1998}$ one requested normative step when the request returns a
committed/terminated state. Rejected self-encryption is represented as an edge
whose destination is the unchanged source state.

This first research slice defines only the conservative exact-state baseline.
It does not claim that any register, memory cell, I/O component, or profile fact
can yet be removed from the graph key.

\section{Exact state projection}

For one execution with complete deterministic input byte string $I$, define
\begin{equation}
  E(s)=\left(
    p,A,C,D,I,i,O,\tau,M[0],\ldots,M[W_{10}-1]
  \right),
  \label{eq:state-graph-exact-key}
\end{equation}
where $p=\texttt{malbolge-1998}$ is the profile identity, $i$ is the committed
input cursor, $O$ is the complete committed output prefix, $\tau$ is termination
state, and $M$ is the complete 59,049-word memory image. This projection is
intentionally larger than a future-relevant minimal state: it is the baseline
against which reductions must be falsified.

Two observations have exact graph identity precisely when
$E(s_1)=E(s_2)$. Replaying the same execution may therefore reuse an existing
node without changing semantics.

\section{Collision-safe indexing}

Let $H$ be any deterministic bucket function, including a deliberately
colliding function. Hash equality is never semantic evidence. The implementation
may merge observations only under
\begin{equation}
  \operatorname{merge}(s_1,s_2)
    \Longleftrightarrow
    H(E(s_1))=H(E(s_2))\;\land\;E(s_1)=E(s_2).
  \label{eq:state-graph-collision-safe-merge}
\end{equation}
Consequently, a collision can increase comparison cost but cannot change graph
identity. The executable test forces $H(E(s))=0$ for every state and verifies
that distinct input strings still create distinct nodes.

\section{Per-step memory mutation bound}

For one requested normative step from memory $M$ to returned memory $M'$, define
\[
  \Delta_M(M,M')=\{a\mid M[a]\neq M'[a]\}.
\]
Malbolge instruction-specific effects can write at most the current data cell
(`crazy` or rotate), and every committed non-halting step can additionally write
at most one self-encryption target. Halt, non-graphical termination, and rejected
self-encryption commit no memory change. Therefore, for both classic and
profile-width execution,
\begin{equation}
  \left|\Delta_M(M,M')\right|\leq2.
  \label{eq:state-graph-two-cell-memory-delta}
\end{equation}
The two addresses may coincide, reducing the observed cardinality. This bound is
independent of total profile memory size and is therefore the semantic basis for
researching persistent/delta memory nodes instead of full per-step snapshots.

The executable correspondence compares complete before/after memories for all
eight instruction families in both classic and current 14-trit states. It
includes real two-cell crazy/rotate witnesses and zero-cell halt/atomic-rejection
witnesses; no private transition-plan metadata is used.

The tracing surface now reports the same actual final changed-cell set without
rescanning memory. Let $D_T(s,s')$ be the set of trace records
$(a,M[a],M'[a])$ emitted for one requested step. The trace contract is
\begin{equation}
  D_T(s,s')
    = \left\{(a,M[a],M'[a])\mid a\in\Delta_M(M,M')\right\}.
  \label{eq:state-graph-trace-memory-delta}
\end{equation}
A data-cell write and self-encryption at the same address therefore produce one
final changed-cell record, unchanged writes are omitted, and halt/rejection
produce the empty set. The executable correspondence reconstructs
$\Delta_M$ independently by complete before/after memory comparison and requires
exact equality with the trace records for every classic/current instruction
family fixture.

\section{Persistent memory reconstruction}

Let $M_0$ be one validated complete profile memory root and let $D_k$ be the
exact trace memory delta for committed request $k$. Define a persistent view
$P_0=M_0$ and
\begin{equation}
  P_k = \operatorname{patch}(P_{k-1},D_k),
  \qquad
  \operatorname{materialize}(P_k)=M_k.
  \label{eq:state-graph-persistent-memory}
\end{equation}
A patch is admitted only when every record's `before` value equals the value read
through $P_{k-1}$ at that address; otherwise construction rejects. Empty deltas
reuse $P_{k-1}$ without increasing depth. By the two-cell bound, each admitted
step contributes at most two changed address/value records independent of the
size of $M_0$.

The current-profile executable correspondence starts from one complete
4,782,969-word checkpoint, applies only `ProfileMemoryDelta` values emitted by
real traced execution, and after every step materializes the persistent view and
requires exact equality with the runtime's complete checkpoint memory. A
separate fixture corrupts a `before` value and requires fail-closed rejection.
Materialization remains an oracle operation; the proposed fast path is shared
root plus bounded patches and exact indexed reads.

\section{Bounded persistent radix overlay}

For the current 14-trit profile, every admitted address is below $2^{24}$.
Partition a 24-bit address into four six-bit chunks and let $O_k$ be a persistent
64-way radix overlay after semantic delta $k$, while $M_0$ remains the shared
complete root memory. The indexed read is
\begin{equation}
  \operatorname{read}(I_k,a)=
  \begin{cases}
    O_k[a], & \text{when an override exists},\\
    M_0[a], & \text{otherwise},
  \end{cases}
  \qquad \operatorname{depth}(I_k,a)\leq4.
  \label{eq:state-graph-indexed-memory}
\end{equation}
Applying a trace delta validates every recorded `before` value through the same
indexed read before path-copying only the affected radix nodes. The bound is on
lookup structure depth, not on total historical patch count. This candidate is
intentionally limited to the 24-bit research domain; wider future profiles must
select a different geometry explicitly rather than silently truncate addresses.

The executable correspondence reconstructs every checkpoint of current traced
execution exactly, inserts 4096 distinct overrides while preserving both latest
overrides and untouched-root reads, and rejects a forged `before` value.

\section{Versioned profile checkpoint baseline}

For a validated profile checkpoint $q$, define the complete checkpoint projection
\begin{equation}
  E_p(q)=\left(
    f_p,I,i,O,\tau,A,C,D,M[0],\ldots,M[W_p-1]
  \right),
  \label{eq:state-graph-profile-checkpoint}
\end{equation}
where $f_p$ is the canonical profile fingerprint and $W_p$ is the exact memory
size declared by that profile. The runtime's `ProfileMachineState` validation is
the authority for whether the checkpoint belongs to this domain; graph research
does not reconstruct or weaken those invariants.

For any deterministic checkpoint digest $H_p$, exact profile nodes may merge only
when
\begin{equation}
  \operatorname{merge}_p(q_1,q_2)
    \Longleftrightarrow
    H_p(E_p(q_1))=H_p(E_p(q_2))\;\land\;q_1=q_2.
  \label{eq:state-graph-profile-collision-safe-merge}
\end{equation}
The current-profile fixture exercises complete 14-trit checkpoints containing
4,782,969 words. Exact replay deduplicates, while a deliberately constant digest
still keeps checkpoints with different input distinct. This establishes a
correctness baseline only; copying/hashing complete current checkpoints is not a
claimed production-performance strategy.

\section{Edges}

Each observed request contributes a deterministic edge from its exact before
node to its exact after node, labelled with decoded instruction (when available)
and normalized result: continued, normative termination, or atomic invalid
self-encryption rejection. Duplicate exact edges are retained only once.

\section{Consumed input prefix reduction}

The normative classic machine can observe an input byte only through the current
committed input cursor. Bytes strictly before that cursor are not read again.
Define the first reduced future key
\begin{equation}
  F_I(s)=\left(
    p,A,C,D,i,I[i\ldots],O,\tau,M[0],\ldots,M[W_{10}-1]
  \right).
  \label{eq:state-graph-consumed-input-prefix}
\end{equation}
Compared with $E(s)$, $F_I$ removes only the \emph{contents} of the consumed
input prefix; it keeps the exact cursor and exact remaining suffix. Therefore
states identical under $F_I$ cannot distinguish prior input bytes through any
future normative input operation.

The executable fixture uses source \texttt{cbO}, which decodes to two input
instructions followed by halt. It exhausts all 256 values of the first byte,
uses one common second byte, and verifies equality of $F_I$ both after the second
input and after the following halt. This correspondence establishes the
reduction only for consumed-prefix content; it does not justify dropping the
cursor or any remaining input byte.

\section{Terminal-state reduction}

Once $\tau\neq\varnothing$, the normative machine returns the same termination
reason on later step/run requests without reading memory, registers, or input and
without committing further output. For already terminated states define
\begin{equation}
  F_{\tau}(s)=\left(p,O,\tau\right).
  \label{eq:state-graph-terminal-state}
\end{equation}
The committed output prefix remains in the key because it is externally
observable history; memory, registers, input bytes/cursor, and other live-state
components are dead for future execution after termination.

The executable correspondence varies valid halt-source memory images, register
values, and input while preserving profile/output/termination and verifies the
same $F_{\tau}$ plus stable repeated termination. A live machine is rejected by
the terminal projection rather than being coerced into this reduced domain.

\section{Reduction research boundary}

A proposed reduced key $R(s)$ is not trusted merely because it hashes or groups
states efficiently. Any rule
\[
  R(s_1)=R(s_2)\Longrightarrow s_1\sim s_2
\]
must declare its domain and be rejected whenever the exact baseline finds a pair
with different future observable behavior under that domain. Until such a rule
has correspondence evidence, native execution may use only exact-state identity
for graph merging.
