\section{Scope}

This document records algebraic reductions that are already consumed by the
Malbolge runtime. A reduction is admitted only on its stated finite/profile
domain and only while its correspondence evidence remains valid.

\section{Classic crazy chunk factorization}

Let $B=3^5=243$. For classic ten-trit words write
\[
  d=d_0+B d_1,\qquad a=a_0+B a_1,
\]
with $d_0,d_1,a_0,a_1\in\{0,\ldots,B-1\}$. Because crazy is digitwise,
\begin{equation}
  \CrazyN{10}{d}{a}
    = \CrazyN{5}{d_0}{a_0}
      + B\CrazyN{5}{d_1}{a_1}.
  \label{eq:optimization-crazy-chunk}
\end{equation}
Therefore one exact $243\times243=59049$ five-trit table is sufficient for both
halves of every classic crazy operation; a $59049^2$ word-pair table is neither
required nor justified.

\section{Profile-width crazy chunk factorization}

For profile width $N$, let chunk width $k=5$, chunk index $j\geq0$, and
\[
  r_j=\min(k,N-jk).
\]
For every admitted chunk with $r_j>0$, define
\[
  d_j=\left\lfloor\frac{d}{3^{jk}}\right\rfloor\bmod3^{r_j},
  \qquad
  a_j=\left\lfloor\frac{a}{3^{jk}}\right\rfloor\bmod3^{r_j}.
\]
Digit independence gives
\begin{equation}
  \CrazyN{N}{d}{a}
    = \sum_{j=0}^{\lceil N/k\rceil-1}
      3^{jk}\left(\CrazyN{5}{d_j}{a_j}\bmod3^{r_j}\right).
  \label{eq:optimization-crazy-profile-chunks}
\end{equation}
The current 14-trit runtime therefore uses chunks $5+5+4$ while reusing the same
five-trit table. The final four-trit result is reduced modulo $3^4$; no phantom
fifteenth trit is admitted.


\section{Exact crazy-target preimage cardinality}

For one ternary accumulator digit $\alpha\in\{0,1,2\}$ and target digit
$\tau\in\{0,1,2\}$, define the data-digit multiplicity
\[
  \mu(\alpha,\tau)
    = \left|\{\delta\in\{0,1,2\}:\CrazyN{1}{\delta}{\alpha}=\tau\}\right|.
\]
For classic words write the fixed accumulator and target in trits as
$a=\sum_{i=0}^{9}a_i3^i$ and $t=\sum_{i=0}^{9}t_i3^i$. Digit independence
then gives the exact full-data-domain preimage cardinality
\begin{equation}
  \left|\{d\in\WordDomain{10}:\CrazyN{10}{d}{a}=t\}\right|
    = \prod_{i=0}^{9}\mu(a_i,t_i).
  \label{eq:optimization-crazy-preimage-cardinality}
\end{equation}
This is an exact finite search bound only for the complete classic data-word
domain under one fixed accumulator. It does not claim that an arbitrary corpus
contains every preimage or contains each data word only once. In particular,
for $a=0$ and the all-one-trit target $t=\sum_{i=0}^{9}3^i$, every digit has
$\mu(0,1)=2$, so the exact full-domain cardinality is $2^{10}=1024$. If any
factor is zero, no classic data word can reach the target for that accumulator.

The complete one-trit crazy table has no accumulator/target pair with more than
two compatible data trits, so $\mu(\alpha,\tau)\leq2$. Combining that fact with
the exact product formula yields the global classic fixed-target bound
\begin{equation}
  \left|\{d\in\WordDomain{10}:\CrazyN{10}{d}{a}=t\}\right|
    \leq 2^{10}=1024
  \qquad\text{for all }a,t\in\WordDomain{10}.
  \label{eq:optimization-crazy-preimage-bound}
\end{equation}
The bound is tight because $a=0$ and the all-one-trit target have exactly two
compatible data trits at every position. This bound applies to complete
classic data-word search only; arbitrary corpora may omit those words or contain
repeated entries and therefore retain their own membership/accounting costs.

The same one-trit table sharpens the cardinality range: every factor in the
product is exactly $0$, $1$, or $2$. Therefore every fixed classic
accumulator/target pair has a preimage count in the discrete spectrum
\begin{equation}
  \left|\{d\in\WordDomain{10}:\CrazyN{10}{d}{a}=t\}\right|
    \in \{0\}\cup\{2^k:0\leq k\leq10\}.
  \label{eq:optimization-crazy-preimage-spectrum}
\end{equation}
Every listed value is attainable. With $a=0$, target trit $1$ contributes
multiplicity $2$ while target trit $2$ contributes multiplicity $1$, so choosing
exactly $k$ target-one positions realizes $2^k$; target trit $0$ in any position
realizes the zero case. This quantization is a complete-domain search-size fact,
not a statement about duplicate or incomplete external corpora.

For a fixed accumulator $a$, let
\[
  n_2(a)=\left|\{i\in\{0,\ldots,9\}:a_i=2\}\right|.
\]
Accumulator trits $0$ and $1$ each have one target trit with multiplicity $2$,
while accumulator trit $2$ has maximum multiplicity $1$. Digit independence
therefore sharpens the worst target for that particular accumulator to
\begin{equation}
  \max_{t\in\WordDomain{10}}
    \left|\{d\in\WordDomain{10}:\CrazyN{10}{d}{a}=t\}\right|
      =2^{10-n_2(a)}.
  \label{eq:optimization-crazy-preimage-accumulator-bound}
\end{equation}
The maximum is attained independently at each digit by target trit $1$ when
$a_i=0$, target trit $0$ when $a_i=1$, and any reachable target trit when
$a_i=2$. Thus accumulator state can tighten the complete-domain candidate bound
below $1024$ before enumeration, without making any claim about an incomplete or
duplicated external corpus.

For the same fixed accumulator, target reachability is also digitwise. An
accumulator trit $0$ or $1$ admits exactly two target trits, while accumulator
trit $2$ admits all three. Therefore the number of classic targets with at
least one data-word preimage is
\begin{equation}
  \left|\left\{t\in\WordDomain{10}:
    \exists d\in\WordDomain{10},\ \CrazyN{10}{d}{a}=t\right\}\right|
      =2^{10-n_2(a)}3^{n_2(a)}.
  \label{eq:optimization-crazy-reachable-target-count}
\end{equation}
This count can reject impossible target states before data-word enumeration.
It is a complete-domain reachability cardinality and does not assert that an
external candidate corpus contains any particular preimage.

The same statistic $n_2(a)$ partitions the complete accumulator domain. For
$k\in\{0,\ldots,10\}$, exactly $k$ positions must be chosen for trit value 2,
and every remaining position independently admits either trit 0 or trit 1.
Hence the exact cardinality of accumulator class $k$ is
\begin{equation}
  \left|\{a\in\WordDomain{10}:n_2(a)=k\}\right|
    = \binom{10}{k}2^{10-k}.
  \label{eq:optimization-crazy-accumulator-class-cardinality}
\end{equation}
Summing these eleven classes yields $(2+1)^{10}=3^{10}=59049$, so the
partition is complete. This grouping is an exact planning classification only;
it does not imply that two accumulator values are semantically interchangeable
outside the two crazy-target cardinalities derived above.

Across accumulator and target digits together, accumulator trit $0$ admits two
target trits, accumulator trit $1$ admits two, and accumulator trit $2$ admits
three. Thus one trit position has exactly $2+2+3=7$ reachable
accumulator/target pairs. Digit independence gives the complete classic count
\begin{equation}
  \left|\left\{(a,t)\in\WordDomain{10}^{2}:
    \exists d\in\WordDomain{10},\ \CrazyN{10}{d}{a}=t\right\}\right|
      =7^{10}=282475249.
  \label{eq:optimization-crazy-reachable-pair-count}
\end{equation}
The complete accumulator/target domain has $9^{10}$ pairs, so the reachable
fraction is $(7/9)^{10}$. This is a global complete-domain pruning fact only;
it does not identify a data preimage or imply a runtime speedup.

The one-trit multiplicity table refines that total further. Among the nine
possible accumulator/target trit pairs, exactly two have multiplicity zero,
five have multiplicity one, and two have multiplicity two. Therefore, for
$k\in\{0,\ldots,10\}$, the number of reachable classic accumulator/target
pairs whose complete data-word preimage has cardinality exactly $2^k$ is
\begin{equation}
  \left|\left\{(a,t)\in\WordDomain{10}^{2}:
    \left|\left\{d\in\WordDomain{10}:\CrazyN{10}{d}{a}=t
    \right\}\right|
      =2^k
  \right\}\right|
    =\binom{10}{k}2^k5^{10-k}.
  \label{eq:optimization-crazy-preimage-pair-distribution}
\end{equation}
Choosing the $k$ doubled positions contributes $\binom{10}{k}$, each doubled
position has two accumulator/target trit pairs, and each remaining reachable
position has five singleton pairs. Summing the classes gives
$(5+2)^{10}=7^{10}$ reachable pairs, while weighting each class by its preimage
size gives $(5+4)^{10}=9^{10}=59049^2$, exactly accounting for every classic
$(d,a)$ input pair. This distribution is a complete-domain search-planning fact;
it does not imply equal semantics between different accumulator/target pairs or
a measured runtime speedup.

The unreachable accumulator/target region is the exact complement of the
reachable region inside the complete $9^{10}$ pair domain:
\begin{equation}
  \left|\left\{(a,t)\in\WordDomain{10}^{2}:
    \nexists d\in\WordDomain{10},\ \CrazyN{10}{d}{a}=t\right\}\right|
    =9^{10}-7^{10}=3204309152.
  \label{eq:optimization-crazy-unreachable-pair-count}
\end{equation}
This count rejects only complete-domain impossibility. It does not imply that a
reachable pair occurs in any incomplete external candidate corpus or that
checking membership is free.

\section{Decode phase reduction}

For graphical cell $m$, decode depends on the code pointer only through its
residue modulo 94:
\begin{equation}
  \DecodeOp(m,c)=\DecodeOp(m,c\bmod94).
  \label{eq:optimization-decode-phase}
\end{equation}
The runtime may therefore precompute one 94-value code phase and a
$94\times94$ graphical-cell/phase table without changing decode semantics.


\section{Self-encryption orbit canonicalization}

Let $G=\{33,\ldots,126\}$ be the graphical-cell domain and let
$E:G\to G$ be the Malbolge self-encryption permutation $E(m)=\EncryptOp(m)$.
The exact $X_2$ table partitions $G$ into six disjoint cycles whose lengths are
\[
  \{2,4,5,6,9,68\}.
\]
For a cell $m\in G$, write $\ell(m)$ for the length of its unique cycle. Then
for every visit count $k\in\mathbb{N}$,
\begin{equation}
  E^k(m)=E^{k\bmod\ell(m)}(m).
  \label{eq:optimization-encryption-orbit}
\end{equation}
Therefore a search state that tracks only repeated committed self-encryption of
one unchanged code-cell address may replace an unbounded encryption-visit count
by the canonical residue $k\bmod\ell(m)$. The reduction applies only when each
counted visit reaches the normative post-instruction encryption phase. Halt,
rejected transitions, writes that change the cell by another mechanism, and
control-flow/address equivalence remain outside this reduction.

\section{Classic rotate lookup}

The classic word domain is finite, so define a table $R$ by
\begin{equation}
  R[x]=\RotateN{10}{x}
  \qquad\text{for every }x\in\WordDomain{10}.
  \label{eq:optimization-rotate-table}
\end{equation}
Replacing scalar rotation by $R[x]$ is an exact finite-domain substitution, not
an approximation or heuristic.

\section{Classic rotate-history canonicalization}

Let $R$ now denote one normative right rotation of a classic ten-trit word. A
rotation permutes the ten trit positions cyclically, so applying ten rotations
restores every word. Therefore, for every $x\in\WordDomain{10}$ and visit count
$k\in\mathbb{N}$,
\begin{equation}
  R^k(x)=R^{k\bmod 10}(x).
  \label{eq:optimization-rotate-history}
\end{equation}
This does not claim that every word has minimal period ten; repeated-trit words
may have a proper divisor as their period. It only gives a safe canonical bound:
a search state tracking repeated rotate updates to one otherwise unchanged
classic data cell needs at most the residue modulo ten. Intervening writes or a
changed data-pointer identity fall outside the reduction.

\section{Verified candidate boundary}

Let $C$ be a candidate set, $V(c,p)\in\{0,1\}$ the independent verifier under
profile $p$, and $\CostVector{c}$ the measured cost vector. Search may rank or
generate candidates arbitrarily, but only
\[
  C_V=\{c\in C\mid V(c,p)=1\}
\]
is eligible for cost comparison. A speedup cannot repair failed semantic
correspondence.

\section{Measured implementation result}

The versioned CPU VM benchmark evidence at
\texttt{benchmarks/interpreter/evidence/2026-07-26-windows-x86\_64/} contains 15
raw
samples per scalar/table implementation and identical checksums. On that
identified host, the classic crazy factorization reduced the median from
77,456,700 ns to 7,423,600 ns (10.43x), while rotate lookup reduced the median
from 15,260,300 ns to 10,141,700 ns (1.50x). These measurements justify the
current CPU implementation on that recorded workload; they are not universal
hardware performance claims.
